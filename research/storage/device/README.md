# Device writes under replicated payment load

Four local Jolteon instances used fresh databases on the same two-device Btrfs filesystem. Each validator ran in a private systemd I/O-accounting scope. The load generator ran on CPUs 0–3, nodes on 4–31, with 32 senders and 4,096 payload bytes per payment. The 600-second and 60-second runs offered the identical 96,000 signed transactions. The churn workload pre-signed 375,000 transactions in 32,768 independent chains. Each transaction after the initial round spends its chain's previous output. The 30-minute aging trial recycled 4,096 chains over 90,000 transfers.

Each confirmed ID appeared once. The verifier authenticated the agreed Header and archived a historical proof. In the chained trial 17,839 transactions missed client dispatch or queue deadlines. Another 79,293 reached a node before a required previously offered output was live or after its predecessor had failed. All 277,868 acknowledged transactions finalized. These dependencies and the client losses affect the measured rate.

The kernel attributed respectively 1.657, 1.419 and 1.354 device bytes per serialized RocksDB batch byte. This is a within-window ratio including journal and finality traffic. Per-node, per-device and logical-namespace deltas are in the [summary](summary.json). Device counters cover filesystem block I/O and can include filesystem metadata. A drive's internal NAND writes are outside this measurement. The SST LOG covers the full fresh fixture, including startup. The 600-second run produced 1,151,026,334 flush and 1,311,606,014 compaction bytes, with 24 distinct compaction jobs creating files.

The [SST block attribution](churn-pressure-sst.json) decodes every key in each captured RocksDB block, assigns each compressed data block and its five-byte trailer to its namespace when all keys agree, and retains mixed blocks and file metadata separately. RocksDB's recorded entry count, range tombstones, data-block count and data size were cross-checked per file. Capture started during the 300-second run and retained 1,271,730,531 of the 5,588,311,571 SST bytes created. Uncaptured files remain marked explicitly. Filesystem overhead, the shared WAL, and drive-internal amplification cannot be apportioned by this decoder.

The 30-minute trial finalized every signed payment, reached agreed height 6,062, and produced 20 compaction jobs with output files. Six written requests returned a client-side resource timeout without an admission acknowledgement. All six IDs appeared in the agreed history. The harness and proof verifier succeeded, and the runner's separate complete-volume assertion failed because it also requires a successful acknowledgement for each request. The measured device/batch ratio was 2.094. Flushes created 584,626,113 bytes and compaction created 236,503,029 bytes. The polling capture retained 720,589,069 of 821,129,142 SST bytes, including all compaction outputs. Fifteen short-lived flush files were missed. Among captured compaction outputs, data blocks exclusive to the proposal journal occupied 89.05 MB, execution 80.42 MB, and live Cells 34.10 MB. The captured inodes span multiple namespaces, so their allocation is reported as mixed. [Aging archive](churn-aging.json.xz) · [SST coverage](churn-aging-sst.json)

At 1,600 independent payments/s the maximum number of acknowledged payments awaiting common visibility was 4,830. Of those waiting at the offer cutoff, 4,326 were still outstanding, and common visibility caught up 4.58 s later. The 30-minute trial peaked at 144 and had 18 outstanding at its cutoff. The [time series](backlog.json) uses each ID's acknowledgement and first all-replica visibility times. Generate it with `python3 backlog.py *.json.xz` from this directory.

### Reproduce

Build the harness with `cargo test --locked --release --test native_store --no-run` and use the unchanged replica from `fefb8cc`. Pass `--device-accounting` to the [runner](../run_load.py) with a dedicated block-backed scratch directory, `--data-bytes 4096 --senders 32 --drain 36`, and the rate and duration in the table. Use `--complete-volume` for the 160 TPS run. For the 300-second and 1,800-second churn trials add `--payment-chains 32768` and `--payment-chains 4096` respectively. The capture program now uses Linux inotify to retain newly created SSTs between directory scans. Check that systemd user scopes and Linux cgroup v2 I/O accounting are available. To record SSTs from the beginning, start `python3 research/storage/sst/capture.py SCRATCH CAPTURE --seconds DURATION` before starting the load. CAPTURE must support hard links on the same filesystem. After the run, build the reader with `c++ -std=c++20 -O2 research/storage/sst/blocks.cc -lsnappy -o /tmp/stem-sst-blocks` and use `python3 research/storage/sst/attribute.py RUN.json.xz CAPTURE/stem-storage-ID /tmp/stem-sst-blocks`. The fixture ID appears in the archived harness log.
